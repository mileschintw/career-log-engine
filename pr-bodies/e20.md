## Summary

An upgrade gave a Log's front page the release's text only above its entries heading. The sections after its entries section (*Upstream*, renamed *Engine repo* in 0.4.1, and *Upgrade*) kept the old wording. The form chosen for #20: text the owner never changed is replaced, with a `done:` line; text the owner changed stays, with a `review:` line, and the mode asks before changing anything there.

```diff
 engine <root> <version>
   checkout the release's Engine paths
   for each front page (README.md, README.zh-TW.md)
     above `## <entries heading>`: unedited -> release's text (done:)
+    entries section: kept as is
+    sections after it:
+      the old Template's or an earlier release's text -> release's text
+        done: <page> after its `## <heading>` section: the Template's text, unedited, now <version>'s
+      the owner's own text, and the release changes the Template's there -> kept
+        review: <page> after its `## <heading>` section: this Log's own text; <version> changes the
+                Template's there, from .build/upgrade/pages/old/<page> to .build/upgrade/pages/new/<page>
```

`skills/career-log/modes/upgrade.md` › step 3:
- A front-page `done:` line goes into step 5's summary.
- On `review:`, the agent shows the release's change (`git diff --no-index` of the two files) beside the owner's text and asks: take the release's text, keep theirs, or a mix. It writes their choice before the step's commit, and step 3's *Done when* checks it.

The earlier-release case matters for the Logs this fixes. Every release from 0.2.0 to 0.3.2 has the same text after the entries section, and 0.4.0 changed it. A Log made before 0.4.0 and moved to 0.4.0 still holds the 0.3.x text, which is Template text, not the owner's.

`page_parts` ends the entries section at the next `## ` heading outside a code fence. A rewritten page keeps its line ends and its byte order mark.

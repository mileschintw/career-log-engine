## Why

`OneExportRunner` (`maintainer/tests/test_coord.py`) and `OneVersionForm` (`maintainer/tests/test_devbuild.py`) read every top-level `maintainer/*.py`, but not every such file ran them. `maintainer/template_checks.py` was in neither `coord-tests.yml`'s `paths:` nor the `coord` or `dev build` group. Locally, `test_devbuild.py` ran only for `maintainer/devbuild.py` and `maintainer/coord.py`. A tool added later had to be listed by hand in three places.

## What changes

- `tools/checks_for.py`: a trigger may hold `*`, which matches any characters but `/`, as a workflow's `paths:` reads it. The `coord` and `dev build` groups take `maintainer/*.py` in place of the files named one by one, so a new tool runs both guards without an edit. The module docstring names the new trigger form.
- `.github/workflows/coord-tests.yml`: `paths:` takes `maintainer/*.py` in place of `coord.py`, `devbuild.py` and `harness.py`. `maintainer/prepush.py` stays listed because the `prepush` group names it and the parity test compares the two. The header comment says why the glob is there.
- `tools/tests/test_checks_for.py`: `test_every_maintainer_tool_runs_both_guards` checks every `maintainer/*.py`, plus a made-up `new_tool.py`, for both guards, and checks that `maintainer/hooks/pre-push` still runs only `test_prepush.py`. `test_glob_trigger` checks that `*` stays within one folder.

The glob replaces the check e32's report suggested (one that fails when a `maintainer/*.py` is missing from the `coord` group). With the glob, no file can be missing from it.

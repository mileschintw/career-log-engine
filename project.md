# Project settings

What relay needs to know about this project. The coordinator and every worker read this file.

- **Repo:** mileschintw/career-log-engine, default branch `master`. Public: this records branch is public too (see **Every push is a publication**).
- **Language:** talk to the user, and write reports, in Traditional Chinese (zh-TW). The plan, `plan-history.md` and briefs are written in Traditional Chinese; repo files, issues and PR bodies stay in English (`docs/maintaining.md › Conversation language`). File paths, technical names and quoted source text stay in their own language.
- **Checks before done:** `py -3 -I tools/checks_for.py --run origin/master` (macOS/Linux `python3 -I`; it prints the checks for the changed paths, runs them side by side once, then its `run:`/`do:` lines; pull request CI already runs Ubuntu 3.11 and Windows 3.13); `sh tools/export-template.sh <scratch dir>`; `py -3 -I tools/skill_lint.py`; `py -3 -I tools/tests/test_skill_lint.py`. A new tool, test or workflow adds its entry to the map `tools/checks_for.py` reads.
- **Local checks:** `py -3 -I tools/checks_for.py --run origin/master`
- **Test bar:** model compatibility phase (`docs/maintaining-tests.md › Model compatibility phase`): an agent case the change touches runs once on Sonnet medium (`maintainer/harness.py ... --model s --effort medium`) and once on Opus medium for no regression; one fix round only (rerun each touched case once and stop; what still fails is logged on the model-compatibility issue; a second round needs the user). This repo holds no Log: build the scratch Log with `maintainer/harness.py template-copy` and fixtures (issue #29 decides the lasting source); never copy the maintainer's Log. Agent cases: the prompt says not to run setup, `tlmgr`, `winget`, `brew` or `micromamba`; HOME, USERPROFILE, APPDATA and LOCALAPPDATA point at scratch; the scratch Log gets a `config.toml` with `update_check = "off"`; fixtures only, never an outside site. A harness process run takes `CLAUDE_CODE_OAUTH_TOKEN` from a token file in scratch that the user fills with `claude setup-token` themselves (`maintaining-tests.md › Harness`); never ask for the token in chat or print it; delete the file after the round and say so in the report. A case that cannot run says so in the report.
- **A test that needs a pull request** (a CI trigger, say): open none; write in the report how to confirm it after the merge.
- **Every push is a publication:** this repo, its pull requests, issues and this records branch are public. Before a push, scan the commit messages (`git log origin/master..HEAD --format=%B`), the diff (`git diff origin/master...HEAD`) and the changed file names against the **Deny list** (whole word, case-insensitive; print paths and line numbers only, never a name), and fix every hit first; the pre-push hook (`docs/maintaining.md`) runs the same scan and blocks the push. PR body drafts, reports, status files and everything in this folder obey the same rule. Expected hits, allowed by the allow list: the owner name inside `<owner>/career-log-engine` or `<owner>/career-log-template` (with or without `https://github.com/`). No content from the maintainer's Log (entries, profile, direction, applications, outputs) ever goes into this repo or this folder, not even paraphrased.
- **Off limits for workers:** the maintainer's Log `D:\Repos\career-log` (read nothing from it unless the brief names a file; write nothing); its `.export-deny`, `.export-cleared` and `.export-allow`: a name that should be added goes in the report as "a name in <path>:<line>", never written out, and the user adds it in their Log. Workers write only their own `status/`, `reports/` and `pr-bodies/` files in the records folder.
- **Ask the user first, with the exact scope:** creating accounts or VMs, installing into the user's real profile, large downloads, signing in to outside sites, spending money; a Mac test (the prompt goes to the maintainer's private records, below); moving or deleting an existing install. Using the user's account for harness runs is covered by their standing approval (2026-10-25).
- **Unattended, never:** publish a Template release or push to the Template; work in the maintainer's Log; archive a session; close an issue other than through a PR's `Closes`; run a Mac test.
- **Release:** `docs/publishing.md` (staging and upgrade test, then a `READY.md`; tag and GitHub Release only on the user's yes).
- **Log format changes:** a change to the Log's data format writes its upgrade into `docs/upgrades/upgrade-next.md` (`docs/maintaining.md › Log format changes`); the brief's Done when says so.
- **Deny list:** `D:\Repos\career-log\.export-deny`
- **Allow list:** `D:\Repos\career-log\.export-allow`, beside the deny list in the maintainer's private Log: fixed strings masked before a scan (the two public repo addresses).
- **The maintainer's private records:** `D:\Repos\career-log-coord` (branch `coord` of the private Log repo) holds the records from before 2026-11-23 and anything that must not be public: Log data prompts (`prompts/TOPIC-prompt.md`, which the user pastes into an ordinary session on `D:\Repos\career-log`), Mac test prompts and their reports, and notes that name people or employers. Write those there, never here; commit and push them there.
- **Log data work** (log, consolidate, data fixes, upgrading the maintainer's Log) is never a lane: write the prompt to the private records' `prompts/` and ask the user to open an ordinary session (no worktree) on `D:\Repos\career-log` and paste it.
- **Outside users' feedback** (an issue or pull request from a Template user): check whether the current `master` already fixes it, discuss it with the user, then triage it; someone stuck goes first.
- **A test session on another machine** (a Remote Control session the user started there): it reports nothing back on its own, and its messages arrive cut short. Reach it by its `ListAgents` name with `SendMessage`, ask for its report in numbered parts (1/N, 2/N, …), ask again for missing parts by number, keep the alarm running until all are in, and save them in order in the private records' `reports/<key>.md` when they may name anything private, else here.
